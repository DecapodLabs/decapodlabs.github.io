# Intent

The public Decapod Labs website explains the repo-native governance kernel and helps humans begin with their existing coding agents. A dedicated offerings.html compares Local with the planned Cloud offering; the homepage links to it without replacing the accepted hero, capability catalog or closing layout.

Local is free, works offline, and requires no signup. Every Get started link on the offerings page goes to https://decapodlabs.github.io/decapod/quickstart.html. Cloud displays Coming soon, shows its planned hosted database, managed sign-in and organization/repository/member management benefits, and has a genuinely disabled purchase button under a second Coming soon sticker. No price, annual term, launch date, checkout URL or live availability promise is published.

## Product Outcome
Help visitors understand the two ways to use Decapod and begin local operation immediately.

## Scope
Dedicated static offering comparison, a restrained homepage entry and preserved branding/media. Authentication, billing, entitlement and hosted storage remain Propodus responsibilities. A coordinated docs navigation change belongs to the Decapod repository.

## Constraints
Preserve current accepted site changes and GitHub Pages hosting. The informational preview does not alter the authoritative Stripe catalog or assert hosted readiness. Source code/history/specifications/worktrees stay repository-native.

## Acceptance Criteria
Local clearly says free and no signup; Get started reaches the exact quickstart URL. Cloud benefits are visible with Coming soon status and a disabled control/sticker, with no public price or purchasing route. Both documents are readable on mobile and desktop. Exact-candidate governed validation precedes publication.

## Decapod Labs website intent

The human-authored source of intent is
[docs/decisions/0001-site-intent.md](../../../../docs/decisions/0001-site-intent.md).
The outcome is an independent, vibrant, public Decapod Labs landing page
at https://decapodlabs.github.io/, linking to existing docs at
https://decapodlabs.github.io/decapod/. AI coding agents operate through
Decapod; humans run init once per project and continue their agent workflow.
Preserve offline-first, bounded authority, current commit-specific proof,
and the actual original film and mascot. Publication must be verified
independently against the publicly served Pages URL.

## Closed-loop metacognitive governance on the public homepage (November 2026)

Retain HARNESS AI METACOGNITION, Meet the Kernel, the approved mascot,
original video, install panel, complete capability catalog, and the existing
distinct brand palette. Explain Decapod's execution contract with a clear,
accessible, mobile-safe presentation: agents respond to governance feedback
while converging on the original prompt and accepted subsequent instructions.
The agent develops falsifiable proof obligations in response to Decapod's
expectations. Separately, validation executes the required checks against the
actual candidate and binds evidence to the identified artifact. A rejection
can inform a new agent iteration; the agent cannot self-approve acceptance.

The homepage must link to the technical convergence manual and preserve the
truth boundary: recorded governed transitions are observable, but the kernel
does not claim access to all internal model reasoning or perfect semantic
correctness. Success requires checking HTML structure, narrow-screen layout,
existing links and functionality, and independent verification of the
published Pages output. A source edit alone never demonstrates deployment.

## Public assurance boundary — adversarial intent review (November 2026)

The homepage explains a closed-loop metacognitive feedback mechanism and the
separate executed validation boundary without promising universal comprehension
of human intent. Passing checks must never be presented as evidence of an
unexpressed want, automatic human approval or proof against arbitrary host
bypass. Ordinary installation and product discovery remain front and center.
Marketing keeps the approved film, mascot, colors, hero and responsive layout.
The kernel owns the actual proof and enforcement contracts; the public site
must never invent a newly implemented external intent oracle.

## Existing governance custody and gate taxonomy (November 17, 2026)

The site must present Decapod validation as the governed acceptance surface
covering recorded intent, scope, task custody, applicable Constitution and
project rules, actual configured execution checks, evidence freshness and
publication policy. Validation is broader than test completion.
The implementation already stores original and refined intent, claims and
trajectory in the single tracked `.decapod/governance.json`; do not imply
a separate intent database or a novel model-based judge. The phase-based
governance loop applies at preparation, implementation, validation and
publication. Keep the existing concise public copy, original film, visual
identity and mobile-safe layout, and preserve the distinction between
observed evidence and unexpressed human meaning.

## Offensive model, bounded evidence (November 17, 2026)

The public homepage leads with Decapod's immediate developer value: the model
can reason, but autonomous work degrades when the surrounding execution loop
loses governing state, repeats failed approaches, or accepts unsupported
completion. Explain the three distinct stages: durable repo-native context,
corrective agent feedback at supported governed boundaries, and the independent
validation of required evidence against the exact artifact. Keep the existing
"HARNESS AI METACOGNITION." hero, brand, film, mascots, installation and complete
feature navigation. Surface the practical outcome before compliance rhetoric.

The runtime does not guarantee interception of all model turns or direct shell
writes. Recovery is supported where Decapod provides an actionable correction;
unproven end-to-end cold-context continuation remains a target tracked in
Decapod issues #1083, #1367 and #1758. Do not suggest that every latent defect,
human meaning, or third-party host is independently proven. The technical docs
must carry the proof/authority limits, while the homepage remains a credible
adoption surface.
