## Pricing and Authenticated Signup Security Boundary (November 21, 2026)

- **Auth-before-checkout and fail-closed commercial gate**: Public `/pricing` keeps `'UNDER WRAPS'` and disabled Pay controls unless server discovery explicitly signals live billing and live sales; even when enabled, Pricing routes through managed PKCE authentication (`https://api.decapodlabs.ai/auth`, fallback `https://goyxpcmxetztjlrrcwew.supabase.co/functions/v1/decapod-onboarding/auth`) to `/signup` and never opens Stripe Checkout directly. `/signup` renders zero organization, repository, or billing state prior to valid PKCE authentication.
- **Input, XSS, and redirect validation**: `cloud-flow.js` validates `?repo=owner/repo` strictly against ASCII owner/repo allowlists, `pricing.js` and `signup/signup.js` update DOM exclusively through `textContent` (zero `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write`), `sanitizeReturnUrl` enforces same-origin HTTPS `/signup` or `/pricing` return targets, and `isAllowedCheckoutUrl` permits only HTTPS Stripe Checkout/Billing hosts.
- **Credential isolation and URL scrubbing**: `signup/signup.js` scrubs all query and fragment parameters immediately via `history.replaceState`, rejects implicit URL fragment tokens (`access_token`, `refresh_token`, `provider_token`), stores active bearer tokens only in per-tab `sessionStorage`, keeps ephemeral provider tokens only in JS memory, and never transmits credentials in URLs or logs.
- **Public-repo confidentiality**: `tests/pricing_signup_test.ts` scans authored website HTML/JS/CSS/TS artifacts and living specs to block Stripe object/secret IDs, private migration filenames, internal RPC symbols, and private backend file paths.

## Browser Asset Release Coherence, Cache Hygiene & Origin Pinning (#70) — November 23, 2026

- **Zero Persistent Cache & `no-store` Enforcement**: No Cloud page uses `localStorage`, `CacheStorage`, or a Service Worker. Discovery (`discoverRuntimeConfig`, `/auth/providers`) and authenticated/quote/checkout/admin `apiRequest` calls enforce `cache: "no-store"`, `credentials: "omit"`, and `redirect: "error"`. Sign-out and `401`/`invalid_token` invalidation clear per-tab `sessionStorage` and in-memory closures (`githubReposCache`, `quoteRequestId`, `enrollRequestId`, form inputs) and notify sibling tabs via zero-PII `BroadcastChannel` (`auth_invalidated`).
- **Fail-Closed Skew Refusal & Anti-Downgrade**: `pricing.js`, `signup/signup.js`, and `admin/admin.js` validate `DecapodCloudFlow.CONTRACT_VERSION === 1`, HTML `<meta name="decapod-flow-contract">`, required DOM anchors, and `initialProfile` origin pins before rendering or calling APIs. Explicit API contract-version mismatches (`decapod-cloud-contract-version` != `1.x` or payload `version !== 1`) fail closed immediately and never silently switch API authority.
- **Deep-Link Scrubbing**: `pricing.js` validates `?repo=` into per-tab `sessionStorage` and immediately scrubs `repo`, `return_to`, `redirect_to`, OAuth callback parameters, and hostile fragment tokens via `history.replaceState` while preserving banner state across asynchronous discovery. `pricing.html` and `pricing/index.html` declare `<meta name="referrer" content="no-referrer">`.

## Organization Admin (`/admin/<org>`) Security Boundary (November 21, 2026)

- **Navigation vs. Authority Separation**: `<org>` path and query locators are treated purely as untrusted navigation hints. `DecapodCloudFlow.resolveAdminOrganization` resolves locators solely against authenticated server `organizations` records to immutable `cloud_org_id` UUIDs, followed by an explicit server-side `account-register` authorization check on that `cloud_org_id` before rendering any workspace panel.
- **Zero-Seat Orthogonality & Repo Data Isolation**: Admin UI never requests or renders repository task, event, or evidence payloads, operating strictly through bounded organization-administration endpoints even when the signed-in admin holds zero paid repository seats.
- **Multi-Org Scope, Abort & Revocation Safety**: Organization switching and sign-out abort active `AbortController` signals, advance monotonic `sessionEpoch` and `renderGeneration` counters, reset all previous-org DOM containers and form inputs, and discard delayed cross-org or post-signout responses. Any `401` (`invalid_token`) clears session storage back to the auth gate and any `403` (`admin_required`, `organization_access_denied`, `admin_revoked`) immediately evicts the revoked org, clears workspace state, and closes the admin workspace.
- **XSS, Redirect & Confidentiality Guardrails**: `admin/admin.js` updates DOM solely via `textContent` and `createElement`/`replaceChildren` (zero `innerHTML`/`outerHTML`/`insertAdjacentHTML`/`document.write`), `sanitizeAdminReturnUrl` restricts OAuth returns to HTTPS same-origin `/admin` routes without userinfo or fragments, Stripe Billing Portal URLs are allowlisted identically to Checkout URLs, and `tests/admin_test.ts` enforces public-repo confidentiality across all authored Admin files and living specs.

## Phase 2–4 Concurrency, Provenance Redaction & Degraded Availability Safety (#54, #55, #56, #71, #72) — November 24, 2026

- **No Trust in Stale Client Caches or Cross-Tab Broadcasts**: `pricing.js` fails closed on manifest release mismatches (`20261124-p3`), clears stale `decapod:pricing-meta` / quote caches, and disables Pay on cross-tab intent mismatch, stale re-probe failure, malformed discovery config, `429` rate limit, or network unavailability. `signup/signup.js` treats `BroadcastChannel` checkout events purely as coordination hints to suppress duplicate Checkout sessions and trigger authoritative server `account-status` verification; `backendAuthorized=true` is set strictly from server-verified `status === "active"` and `backend_authorized === true`, never on `pending_timeout` or Browser Back/reload.
- **Support-Safe Correlation References & Bounded Retries (#71)**: `DecapodCloudFlow.extractCorrelationRef` extracts only opaque identifiers (`x-request-id`, `x-correlation-id`, `cf-ray`, `request_id`), explicitly rejecting JWTs, OAuth/API tokens, and PII. `createBoundedPoller` stops immediately on `401`/`403` and honors bounded `Retry-After` on `429`. Lost checkout acknowledgements and `pending_timeout` retain stable `request_id` / `checkout_pending` metadata while explicitly advising against duplicate payment.
- **Provenance Non-Authority & Automated Redaction (#72)**: `tests/provenance_projection_72_test.ts` enforces zero secret/token/PII leaks across all published `evidence/*`, `media/*`, `assets/*.json`, `proof.html`, and `index.html`, verifies deterministic witness/event/receipt digests, rejects tampered/superseded/stale-green references, and ensures projection republishes never rewrite canonical archive receipts.
