Evaluation Method & Findings

Evaluation method

The seeded repository’s configured suite (authorization-contract; 10 assertions plus source guard in the earlier fixture) executed through native decapod validate and correlated across independent GitHub readback.

Source change (ed086de6 → a063de90)

Between candidate failure and verified head, the agent closed the repository-grant check so ungranted member reads fail closed inside the isolated worktree.

Invalidation triggers

Mutating source commits without fresh validation or advancing the accepted base invalidates prior admission (see negative controls below).

Observed scope

Documents one bounded run with correlated checks and PR admission; check results do not generalize into an unconstrained autonomy claim (see boundaries).

What actually happened

  1. The agent consulted Decapod, claimed a task and entered an isolated workspace.
  2. Initial specification/governance rejections provided actionable feedback. These do not count as the engineering failure.
  3. The accepted authorization check executed and failed: a member without a repository grant was incorrectly allowed access. The process exited 1.
  4. After receiving that failure, the agent inspected the actual output and changed repository-scoped access logic.
  5. Fresh execution passed all required checks. Decapod published and verified real GitHub PR #2. Independent readback matched both the validated head and accepted target.

A green result expires (operator-owned negative controls)

Separately labelled operator-owned probes followed the completed agent run. They did not change the agent’s source branch or supply its repair.

  • A source mutation after real PR creation returned PR_CREATED_NOT_ADMITTED and WORKUNIT_PROOF_STALE. Decapod confirmed draft quarantine for probe PR #3.
  • A subsequent source mutation was rejected with GOVERNANCE_CHECKPOINT_MISSING; historical proof could not publish it.
  • Advancing only the issue-owned target returned STALE_ACCEPTED_BASE, including on repeated validation. The new target is ada3eb89c3707801a5b86265dccc899fdabe5e1c.

PR #2’s admission is historical; its current applicability is false. Its exact head is preserved, and it was made draft after the target control. No merge is authorized. The original archive and historical PR #1 remain untouched.

Assurance boundary

Digests bind captured bytes; they do not authenticate a producer. Host provenance is a trusted operator assertion with bounded tool-boundary observation. This is no universal OS sandbox or guarantee about uncaptured activity. The model provider exposes an alias, not immutable weights. This small seeded task is one observed run, not comparative evidence of general agent reliability. Native local checks do not attest a hosted CI matrix. PR admission never authorizes merge.

The kernel enforced admission through its native publisher. The observer only reports what it captured and cannot admit a PR. No independent GitHub enforcement of the fixture’s admission policy or prevention of every direct forge bypass is claimed. Offline observer regressions cover bypass and false-completion classification; the kernel source repository’s required CI policy is a separate control.

No Cloud purchase or hosted onboarding success is depicted. The local-first demonstration requires no Cloud subscription.
