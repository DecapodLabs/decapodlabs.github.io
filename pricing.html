GOOD TO KNOW

Clear terms.
Real control.

Clear answers on licensing, usage, and approvals.

Do we need to change our coding agents?

No. Keep Codex, Claude Code, Cursor, Antigravity, or a combination. Your agents call Decapod automatically when needed. Each call returns a result and exits, while governance state stays with the project.

What is a contributor–repository assignment?

One human assigned to one repository is one paid assignment. The same human assigned to two repositories uses two assignments. Contributor-volume savings count distinct people only once per customer.

Do coding agents count as seats?

No. Agents, subagents, and worktrees are not additional human seats. Their Cloud activity still consumes measured resources.

How does workforce sign-in work?

Sign in with Google or GitHub. A single person can belong to multiple organizations, with explicit repository-specific access and paid assignments. GitHub repository linking requires verification of the corresponding GitHub identity.

How are subscription savings calculated?

Repository count and distinct contributors each determine a volume tier. The preview shows the minimum for your selection; final pricing uses verified assignments. Annual billing adds 8 percentage points to volume savings, up to 20% total on the base subscription. Resource overages receive no discounts.

Can we set limits and alerts for each resource?

Yes. Cloud Admin supports configurable limits and warnings for network transfer, compute and operations, retained database/evidence storage, and request pressure. These settings can warn you early or restrict your own usage; they cannot raise included allowances or bypass platform safety limits. Alerts never authorize billing.

Will Cloud charge me automatically if I exceed a resource limit?

No. Paid overages are disabled by default. Without your organization's authorized admin explicitly enabling them in Cloud Admin, new usage beyond included limits is throttled or declined with no overage charge. Admins can opt in after reviewing disclosed per-resource rates and setting a spending cap. Only authorized excess usage is billed, itemized by resource.

What will we know before subscribing?

Cloud prices, included resource allowances, and any excess-use rates will be disclosed before enrollment. Charges for excess use are off by default and require separate approval from an authorized billing admin, with a spending cap.

What if we're bigger than the sliders?

Talk with sales for more than 10 repositories, more than 25 contributors per repository, or specialized deployment and capacity needs.
