PRODUCT BOUNDARIES

What runs locally, and what touches the network.

We distinguish strictly between offline local-first products and explicitly enabled hosted services. We never claim a hosted service observes nothing, and we never advertise unqualified zero-network claims for cloud features.

01 / DECAPOD LOCAL CLI & CORE

Zero telemetry. Zero analytics.

Running decapod in default local mode stores governance state, SQLite databases, trajectories, and proofs strictly inside your local repository.

  • No background daemon, heartbeat, crash reporter, or usage beacon.
  • Local observability projections remain read-only files in your repository with no default upload.
  • Network egress occurs only when you explicitly configure Cloud backend mode or invoke an explicit remote command.
02 / DECAPOD CLOUD (HOSTED)

Strictly declared service endpoints.

When you opt in to Decapod Cloud, hosted APIs necessarily process authenticated identity, repository-scoped task/proof traffic, and billing state.

  • Declared endpoints only: GitHub OAuth & API (and optional GitLab when enabled), Supabase Auth/PostgREST/Edge Functions, Stripe API for billing, and our first-party Cloudflare Worker API gateway.
  • Zero third-party analytics SDKs, ad networks, or tracking pixels on the website, Cloud Signup, or Cloud Admin.
  • Minimal operational diagnostics scrub credentials, tokens, emails, and DSNs before logging.
03 / DACTYL STORAGE ADAPTER

Local SQLite = zero egress.

Dactyl provides bounded, origin-validated storage transport with explicit backend selection.

  • Local SQLite mode: Performs zero network egress outside loopback test fixtures.
  • Optional remote modes (neon / supabase): Enforce HTTPS-only connections, strict origin validation, and disabled cross-origin redirects.
04 / CLACK FOR MACOS

Local workspace isolation & opt-in boundaries.

Clack keeps project files and home-directory state local while making external integrations explicit user choices.

  • Local models: Loopback Ollama communication stays on your machine.
  • Coding agent providers: Subprocess execution invokes only the coding agent executable you select; that provider's own CLI and ambient environment form an explicit external trust boundary.
  • Solana & Browser: Solana mainnet RPC runs only for deliberate wallet actions; the built-in browser navigates only where you direct it.

CLOUDFLARE WORKERS RELAY TRANSPARENCY

What our API gateway sees, forwards, and refuses to keep.

Public API traffic at https://api.decapodlabs.ai passes through a stateless Cloudflare Worker relay to our primary Supabase backend. Here is the exact operational boundary.

OBSERVED AT EDGE

Transient request metadata

  • TLS-terminated HTTP method, host, route path, and query string (capped at 8,192 bytes).
  • Client authorization and signature headers forwarded for upstream validation.
  • Edge response status and Cloudflare Ray timing metadata.
STRIPPED & ATTESTED

Header normalization

  • Strips caller-supplied proxy spoofing headers (X-Forwarded-Host, Forwarded, and unauthenticated proxy headers).
  • Signs bounded HMAC-SHA256 route attestation headers for DPoP URI verification.
  • Forwards raw webhook payloads untouched and enforces redirect: manual.
NEVER RETAINED OR EXECUTED

Zero Worker persistence

  • Zero request-body, JWT, DPoP key, or webhook secret logging in Worker code.
  • Zero KV, D1, R2, or Cache API persistent storage bindings.
  • Executes no database queries and fails closed on unknown or traversal paths (404 / 503).

PERMANENT GUARANTEES

Nine permanent trust invariants.

These invariants govern architecture, engineering reviews, and automated verification across Decapod, Dactyl, Propodus, Clack, and decapodlabs.ai.

01 / DATA SCOPE

Purpose minimization

Only fields strictly needed for the selected action are transmitted. Ambient home-directory secrets and unrelated repositories are never read or uploaded.

02 / AUTHORIZATION

Fail-closed boundaries

Cloud operations require verified JWT + local AAL2 MFA step-up for sensitive changes, RFC 9449 DPoP proof-of-possession, and tenant-scoped RLS.

03 / RETENTION

Explicit lifecycle separation

Sensitive payloads can be redacted and garbage-collected without falsifying immutable structural audit digests. Legal retention stays governed by explicit policy.

04 / CONSENT

Default-OFF paid overages

Paid overages are off by default with zero silent spend. Enabling overages requires an explicit billing-admin action, versioned terms consent, and a finite spend cap.

05 / REVOCATION

Effective immediately

Revoking a device key, session, provider link, or repository grant takes immediate effect at the control plane; refresh token reuse revokes the entire session family.

06 / SOVEREIGNTY

Identity sovereignty

Accounts across GitHub, Google, and GitLab are never silently auto-merged. Linking requires live authenticated session continuity and explicit user confirmation.

07 / NO FINGERPRINTING

Zero cross-site tracking

Zero browser fingerprinting, zero third-party analytics, zero ad pixels, and zero cross-tenant correlation via unhashed identifiers.

08 / CREDENTIAL ISOLATION

Strict key boundaries

Provider tokens stay isolated to their fixed origin; billing keys are pinned to Stripe; administrative DB credentials are forbidden in routine operations.

09 / INTEGRITY & ACCOUNTABILITY

Verifiable artifacts

Release downloads include SHA-256 checksums, commits are cryptographically signed, backups are AES-256-GCM verified, and telemetry passes zero-leak checks.

INCIDENT ACCOUNTABILITY & REVOCATION

How to report a concern or revoke access.

Security disclosures, privacy questions, and suspected credential exposures are handled directly by Decapod Labs maintainers with deterministic containment and commit-bound evidence.

Disclosure & Revocation Channels

  • Security & Privacy Advisories: Submit a private vulnerability report via GitHub Security Advisories ↗ or open an issue on DecapodLabs/decapod ↗ for non-sensitive contract questions.
  • Self-Service Revocation: Revoke enrolled device keys and active sessions immediately from Cloud Admin or via the CLI device-revocation flow.
  • Response Commitment: Suspected token or egress anomalies trigger immediate key rotation, fail-closed access fencing, and redacted post-incident verification tied to exact commit SHAs.
